# OpenRealm · Pitch

## 30 秒开场

今天一个游戏世界通常由一家工作室独自开发和经营。独立创作者即便想加入，也缺少统一的玩家身份、模块权限和合作收益协议。OpenRealm 提供这套共同基础：一个世界，多位创作者，共享身份与透明分账。

## 2 分钟讲稿

我们从一个很小、但完整的合作场景开始：Aetheria。

第一位创作者构建免费的 Mystic Forest，第二位构建收费的 Arcane Forge。玩家领取一份 World Passport，在两个模块使用同一链上身份；进入工坊时支付测试 MON，合约把 80% 记入创作者待提取余额，20% 记入世界公共金库。

这体现三个改变：生产从一家工作室扩展为多个创作者；身份由共同协议识别；经济合作由公开规则记账。我们选择兼容 EVM 的 Monad，让 Solidity 合约与前端钱包可以共用成熟工具。

今天我们验证的是共同身份、模块权限和收益分账。共享资产仅限 Passport，还没有装备互通、开放治理或自动 IP 授权。初期管理员控制注册，未来逐步完善许可和治理。

我们的目标不是做两个孤立小游戏，而是证明两个独立作者可以通过同一协议，为一个世界创造内容，并共享合作成果。

We don't need one big studio to build one big world. We need a shared protocol that allows independent creators to build it together.

## 评委问答

- 和游戏商城的区别？商城以分发为主，这个 MVP 聚焦共用身份、模块权限与合作收益约定。
- 为什么上链？参与方能共同核验身份所有权、购买记录与待提取余额；游戏画面仍在前端。
- 分账是否到账？购买时记账，收款方调用 withdraw 后到账。
- 资产是否真的互通？只有 Passport；不宣称装备、背包互通。
- 开发者是否完全开放？MVP 管理员注册；开放许可与治理是后续工作。
- IP 怎么解决？智能合约不解决著作权；演示内容为原创或获得许可，商业合作还需要法律协议。
- 当前完成程度？根据实际演示环境回答；Mock 仅产品彩排，链上证明以 B 的真实交易为准。
